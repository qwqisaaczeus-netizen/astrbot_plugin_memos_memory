# AstrBot Memos Memory 5.0.0-test0 实现与验收报告

## 1. 发布定位

本版以 `4.6.2` 为唯一功能基线，实现 5.0 大纲中的“非破坏式记忆遗忘、可达性与再巩固”第一阶段。这里的遗忘只表示记忆的自然访问难度发生变化，不表示删除、覆盖、截断或降低历史事实可信度。

`test0` 固定为 Shadow 观察版：新系统真实建库、维护、计算、模拟、记录诊断，但正式聊天继续使用 4.6.2 的候选选择、融合注入、时间边界与安全网结果。这样可先用真实查询检验新算法，再决定后续是否接管主路。

## 2. 兼容与数据边界

- 版本：`5.0.0-test0`。
- 数据库：`episodic_memory.db` schema `6 -> 7`。
- 升级前：复用现有迁移保护，自动创建本地数据快照。
- 保留不动：Memos 正文、原文批次与轮次、Episode、证据链接、滚动状态及版本历史、画像、心潮、身体节律、时间洞察、上下文治理与备份。
- 新增数据全部为可重建派生数据；删除派生表后仍能从 Episode 恢复，不会反向改写 Memos。
- 任一 5.0 模块异常均 fail-open，当前请求继续走 4.6.2。

## 3. 统一访问状态

每篇记忆维护以下连续维度：

| 维度 | 当前实现 |
| --- | --- |
| `persistence` | importance、实际记忆类型、长期影响及未解决事项共同决定；人格、承诺、边界、规则和关系转折额外保护。 |
| `vividness` | 以真实事件时间衰减，人物、原话和细节可增强；升级建状态的时间不冒充事件时间。 |
| `distinctiveness` | 日期、实体、原话和全库线索稀有度共同描述区分能力。 |
| `grounding_bonus` | 原文可回、用户编辑等证据质量只提供正向加成；旧 `diary_derived` 日记不受惩罚。 |
| `interference_load` | 只由类型化干扰边产生，并设有限幅。 |
| `inhibition` | 作为暂时访问覆盖层保留，不成为永久状态。 |
| `accessibility` | 综合持久性、鲜明度、独特性、证据、再巩固和干扰得到自然可达性。 |

连续值归纳为 `vivid / latent / deep` 三态，切换使用迟滞区间，避免每天维护时在阈值附近反复跳动。基础衰减周期默认 45 天，但会按 persistence 自适应伸缩；它不是到期删除时间。

## 4. 线索签名与深层救回

每篇 Episode 建立可重建线索签名：日期、人物与实体、原话、retrieval key、scene anchor、trigger hint 和正文关键词。日期统一为 `YYYY-MM` 或 `YYYY-MM-DD`，因此 `2022-03-14`、`2022年3月14日` 等查询可对应同一事件日期。

Shadow 评估同时读取：

1. 4.6.2 融合相关分。
2. 词面、向量、时间、原文等已有路线支持。
3. 日期、实体、原话和稀有词的线索支持。
4. 自然可达性、干扰负载与受限心理偏置。

深层记忆不会被永久否决。明确日期、原话，或实体与内容共同形成的强线索可触发救回建议；弱泛问不会仅因语义相似自动突破深层状态。

## 5. 类型化干扰图

5.0 不再把“相似”直接等价为重复，而是建立五种边：

| 边类型 | 作用 |
| --- | --- |
| `same_event_restated` | 同日、同实体、同一事件的重复表述产生主要竞争。 |
| `same_theme_distinct_event` | 主题相似但日期或结果不同，只施加极弱竞争。 |
| `contradictory_stage` | 不同关系阶段的真实矛盾作为时序证据保护，竞争上限很低。 |
| `causal_chain` | 前因后果共同覆盖，不施加淘汰式竞争。 |
| `shared_surface` | 仅词面接近、证据不足时只产生微弱访问成本。 |

每篇默认最多保留 12 个高价值干扰邻居。图只服务于访问诊断，不合并日记、不删除成员，也不限制真实注入条数。

## 6. 回答使用与再巩固

系统区分“进入候选”“被正式选中”和“回答确实使用”三件事。回答后会用线索与实体覆盖检查模型是否实际利用了记忆，并记录请求级事件。

在 `test0` 中，这些证据只进入日志和 WebUI，绝不增加 reconsolidation count，也不反过来影响下一轮正式召回。未来非 Shadow 版本只有在回答确实使用且再巩固开启时才允许增强；单纯被搜索到不会变强。

## 7. WebUI 与操作入口

新增独立页面“记忆可达性”，与心潮、记忆生产、Console 分离。页面包含：

- 三态数量、平均可达性、干扰边和最近维护状态。
- 按状态检索记忆及维度条形显示。
- 单篇记忆的线索、维度、邻接干扰和访问事件。
- 可点击的类型化干扰关系图。
- Shadow 召回实验：同屏对比 4.6.2 实际名单和 5.0 建议。
- 派生层重建与维护操作。

旧命令 `/memos-cluster-rebuild` 及其关系图谱别名在 5.0 开启时改为重建可达状态、线索签名与类型化干扰图。关闭 5.0 时仍回退原实现。

## 8. 新配置

新增总开关、Shadow 预留位、衰减、深层救回、类型化干扰、再巩固、心理偏置、三态阈值、基础衰减周期、精确线索抵消比例、最大邻居、维护周期和事件保留量。全局预设只调整数值与开关，不会修改 Token、Memos 地址、角色名、Provider、端口或数据路径。

`memory_forgetting_shadow_mode` 在 test0 中固定为开启。即使旧配置或 WebUI 写入 `false`，运行时也不会让未验证算法接管真实召回。

## 9. 预期收益与当前边界

本版已经解决的是“如何完整建立可达状态、精确线索、类型化竞争和真实使用证据”，并提供可观察、可模拟、可重建的数据闭环。它不声称已经提高正式聊天命中率，因为 test0 有意不改变正式名单。

后续接管必须以真实评测为前提：比较 4.6.2 实际名单与 5.0 建议名单的 Hit@K、错误干扰、深层救回和注入使用率。只有对旧日常、不同日期相似事件、关系矛盾阶段、明确日期和原话等关键样本验证通过，才应逐步开放“只影响呈现精度”或“影响排序”的阶段。

## 10. 验收范围

发布前执行：Python 静态编译、配置解析、HTML 内联脚本语法检查、5.0 专项测试、当前 AstrBot 完整测试、旧 AstrBot 兼容测试、源码审计、ZIP 审计与压缩包结构检查。

本次发布验收结果：

- 5.0 可达层专项：14/14。
- 当前 AstrBot `4.26.8` 完整回归：289/289，零失败、零错误、零跳过。
- 旧 AstrBot `4.25.1` 完整回归：289/289，零失败、零错误、零跳过。
- WebUI：`access.html`、`dashboard.html`、`production.html`、`xinchao.html` 全部通过内联 JavaScript 语法解析；实际 HTTP 页面与可达层 GET/POST API 已进入完整测试。
- 源码审计：当前与旧 AstrBot 根目录均通过；版本、schema、插件入口和运行文件检查一致。
- `sqlite-vec` 在测试环境未安装，测试按插件既有设计使用 Python cosine fallback；这不是发布失败，也不改变用户已配置环境中的 sqlite-vec 路径。
