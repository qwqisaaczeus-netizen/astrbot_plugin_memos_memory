# AstrBot Memos Memory

> **6.1.0 正式封包：清蓝工作台。** 基于 RC6 A 测试修正版，统一总览、心潮、月历、记忆生产、调度中心、补偿与控制台的视觉系统。主色只用于操作与选中状态，成功、警告、错误独立显示。注入构成新增可聚焦色带，月份分布改为真实数据柱条，月历支持同日多篇与明确的空日状态。导航选中态与菜单展开态分离，修复总览和记忆栏目同时高亮。保留原有 API、设置、模型路线和记忆机制，不自动重跑旧作业，也不打开遗忘接管。

> **6.1.0-rc6：证据解释核验与选择性文学写作。** 新生产在精确引文抽取后追加一次有调用上限的语义核验，区分人物归属、意图与完成事实。新 `literary-v4` 区分正文关联、背景参考和证据库留存，保留第一人称与文学性；不再把 `fact_ids` 数量当成正文已覆盖的证明。中文原文进入词面索引，旧英文解释也可以按中文原文检索。详见 [RC6 设计与升级边界](DESIGN_610_RC6.md)。

原始 RC6 发布前仅进行了免费离线和本地 HTTP/SSE 故障模拟。本同版本 `rc6-a-fix` 构建增加一次授权的真实 A 测试：9 月 27 日批次原文副本，38 条消息，最多且实际使用 12 次模型请求，不写 Memos、不更新滚动状态。原版 RC6 在兼容性与容量校验处未跑通，隔离修正后生成三篇 921、1318、750 字的第一人称日记，并通过本地检查与模型审稿。一次样本成功不能证明所有模型、网络和文学质量都稳定。旧作业保留冻结模型、提示词与费用预算；升级不会自动重跑旧批次。详见 [A 测试兼容修正](DESIGN_A_RC6_FIX.md)。

> **RC3 单模型测试包（call-test）**：在调用打磨包基础上，新增外置/跟接模型的上下文窗口容量声明，以及调度中心的 Astr、外置模型单次调参测试。模型窗口不是聊天保留轮数，也不能扩展供应商实际容量。测试需确认费用，不自动重试、不写入记忆，不覆盖正式参数。详见 [测试与模型窗口](MODEL_PROBE_RC3.md)。

> **RC3 调用打磨包（call-polish）**：调度中心新增逐任务流式、思考模式/强度、输出预算和读取空闲超时。默认开启流式；修正主路/跟接参数不一致与草稿入口漏跟接，保留截断和空正文诊断。参见 [调用设置与兼容边界](CALL_POLICY_RC3.md)。安装不会自动重跑旧批次；真实模型重跑尚未验收。

> **6.1.0-rc5：文学日记、最终证据绑定与分级评审。** 写作前分组不再限制合理的同批素材重组；发布日期、原文引用和召回投影跟随最终正文重新绑定，完整证据不删。事实错误仍阻止发布，纯叙述顺序和风格意见只作建议。新增有审计的零调用局部修订，保留旧稿和旧审稿结果，不伪称模型复审通过。详见 [RC5 说明](DESIGN_610_RC5.md)。RC4 的流式进度闸门、短引用抽取和旧作业预算保护保留，升级不会自动重跑旧批次。

面向长期角色扮演的 AstrBot 记忆插件。它把聊天沉淀为可追溯的原文档案、结构化 Episode、第一人称文学日记和滚动当前状态，再通过全 MEMORY 融合检索与非破坏式遗忘，让角色既记得具体发生过什么，也能在年月尺度上形成连续的关系与人格。

## 快速开始

### 安装与升级

1. 备份插件数据目录和配置，安装 ZIP 并重载插件，强制刷新浏览器。无需重新同步或重建旧记忆。
2. 打开记忆生产的「6.1 草稿与迁移」。当前链路明确显示兼容生产、新生产或等待确认，不把安装成功说成已接管。
3. 先选择一个原文批次、模型及调用上限，生成草稿。这一步会收费，但不会写入 Memos。关闭网页不取消后台任务。
4. 检查草稿和调用记录。失败时展开作业，选择补齐未完成阶段、重写正文、重做规划或重新抽取。需要新增预算时显式确认，旧作业与费用记录保留。
5. 准备使用新生产时点击「启用新生产」，确认费用、备份和 Memos 固定 ID/事件日期支持。后续普通、手动和夜间压缩进入新链；已有草稿不会因此偷偷发布，仍需点发布。
6. 旧内容不是自动重写。先生成迁移预检，再为相应原文批次生成证据；有完整原文的旧日记可以「应用证据升级」，也可以撤回。无原文日记继续原有检索，不虚构原文。

心潮统一调度默认开启，但不会打开此前关闭的心潮功能。保留即时评估、聊天后评估、梦境等原有入口、提示词和模型选择；仅替换请求调度边界。可关闭 `generation_v2_mind_enable` 回到原调用边界。新调度记录可在生产页查看。

新生产默认不自动启用，原因是它会触发付费模型和 Memos 写入，需操作者确认；不是只有一个不能工作的开关。失败保留原文，暂停/取消不删除原文；该批次仍归新生产所有，不会交给兼容链重新收费。已有远端发布清单时只允许继续交付，不允许覆盖式重写。

### 工作台与调度中心

正式版使用统一的清蓝工作台：浅灰页面、白色记录表面、清蓝操作与选中态，独立的成功、警告、错误颜色。总览、心潮、月历、生产、模型、补偿、可达性分析与控制台使用同一套字体、间距和控件。模型与记忆逻辑沿用 RC6 A 测试修正版。

保留横向导航和任务编辑侧栏。概览的原文、滚动状态、文学日记、情景证据均读取实际统计，不包含演示数据；小院继续保留完整院落场景。注入构成色带可联动已有明细，月份统计改为柱条，月历中叠页标记表示同日多篇。正式 UI 不改变接口或增加模型调用。详见 [清蓝工作台设计](DESIGN_610_CLEAR_BLUE.md)。

调度中心可以直接点开任务路线，在侧栏分别选择主模型与跟接模型；底层参数按需展开。若主模型已保存但跟接保存失败，会明确显示部分成功并允许重试，不会误报全部成功。更新后请重载插件并强制刷新浏览器，清除旧静态资源缓存。

直接更新插件并重载即可，不需要同步、重建索引或重新生成日记。已有配置、密钥、原文、日记、状态和作业记录沿用原位置，不随界面更新重置。

- 主导航按记忆、心智、运行维护分区；诊断工具折叠收纳。概览保留图表和关键运行状态，详细状态按需展开。
- 插件设置改为分类折叠与搜索，模型、调用超时和并发参数转到 `/models` 调度中心。心潮仍管理心理与身体策略，小院仍管理院落行为；两者独立 API 的配置入口移入调度中心。
- 调度中心包含任务分工、跟接策略、外置模型、独立通道、调用记录。模型池与任务跟接共用一份持久化配置；保存只更新所属配置，不重置角色、Memos Token 或其他页面参数。
- 新增 `narrative_plan_provider_id`、`diary_review_provider_id`。新生产中的证据抽取、叙事规划、写作、审稿可分别指定模型；留空继承压缩模型。新链的叙事规划会调用模型，不能误认为单分片必然是免费本地规划。
- 跟接支持任务专属模型、继承类别默认、明确禁用三种状态。优先级为任务设置高于类别默认；总开关关闭则全部不跟接。不开模型池接管，也能单独使用 Astr 故障后的 API 跟接。
- 路由不改变重试次数、截止时间、总调用预算或失败发布闸门。RC1 在途作业继续使用原合同；RC2 新作业冻结各阶段路线，不能通过换模型或刷新页面重复花费。
- 心潮独立 API、小院独立 API 仍是各自的专用通道，不暗中合并成模型池；Embedding 和 rerank 仍手填原 Provider ID。生产页一次性草稿的显式模型选择属于执行参数，保留确认费用的流程，不改全局任务设置。

模型选择修改一般用于后续调用；并发和部分服务参数保存后提示重载。6.1 生产使用其独立调度合同：每次模型请求默认 180 秒，Astr 通道最多 6、独立通道最多 10，单端点最多 2、单作业最多 2。调度中心显示的旧 Runtime 并发和兼容链路超时不是修改既有 6.1 作业合同的入口。

### RC1 受控草稿与恢复

安装不需要同步、重建或迁移旧日记。进入独立“记忆生产”页的“6.1 草稿与迁移”，选择已存原文批次和模型，再按“生成草稿”。确认框会明确提醒模型费用；总调用上限默认 8 次，包含重试、写作、审稿，不是并发数。草稿默认最多 3 篇，这只是上限。

关闭页面不会取消任务；重新打开可查看状态与已保存草稿。重复提交相同批次、模型和参数会复用任务及已成功结果，不强行重新生成。不要用变更模型或预算的方式绕过失败记录：同一任务的合同固定，过期或耗尽的任务目前需要后续明确的修订机制，不会自动追加费用。

迁移预检无模型调用，不更改旧记录。WebUI 草稿入口仍不会自动发布。新增自动生产入口与草稿入口共享同一调度服务：在设置中启用 `generation_v2_enable`，并确认目标 Memos 支持自定义 memoId 和事件 createTime 后启用 `generation_v2_memos_capabilities_confirmed`，后续普通、手动和 23:45 压缩才进入新链路。未确认发布能力时保留待处理原文，不调用模型。单批调用预算 `generation_v2_job_cap` 默认 12，包括重试与跟接，不是篇数或并发数。

发布必须整批合格、远端回读一致、Episode/原文关联投影验证通过，并交入滚动状态队列后，才清理已处理的缓冲序号。失败保留原文和批次归属；交付失败恢复不重新写作。关闭新开关不会把它已接管的未完成批次退回旧压缩链。生产页增加自动交接状态及下次可恢复时间。滚动状态仍沿用既有低频/变化轴策略，不强制每批立即调用模型。

新证据接入既有 Episode 向量检索及精简主召回的词面补充，参与同一 rerank/筛选/注入流程，不另外强塞固定篇数。未进入日记正文的事实仍保留；未激活、已回滚或其他会话的新版发布记录不会进入本轮注入。单作用域实验室可自动选择唯一发布作用域，多作用域不自动混查。心潮和时间治理未重构。

生产作业展开后可查看实际调用次数/上限、各次耗时、失败类别、模型返回的 token 用量及写作合同版本。未返回用量显示费用未知，不显示为零。自动交接批次已经有发布清单但交付未完成时，提供“恢复交付”：仅对账、发布、补建索引及交接状态，不重新调用取证、写作或审稿；补索引仍可能调用 embedding，确认框会提示。关闭网页不取消恢复，卸载/停止插件会取消其本地在途任务，远端是否已计费不能保证。

RC1 不自动改写已有合格草稿。旧任务沿用 `literary-v1` 固定合同，新任务使用 `literary-v2`；这避免升级时改变任务指纹而重复生成或追加费用。新提示词明确源对话语言、角色第一人称、人物行为归属、原文记录时间与故事时间的区别，以及非流水账、非逐句改写的文学要求。默认 250～900 字仍只是写作参考，1800 字硬上限和单次修订保持原有配置合同；短经历不强制凑字。提示词改善不等于已证明文学质量改善。

### 6.0.0-rc8 更新说明

RC8 同时打磨模型故障路线和日记成稿质量，不改变主召回、注入、时间锚定、心潮状态、遗忘数据或小院。

- Astr 请求发生 `Connection error` 等传输故障时，由插件明确再给同一模型一次机会，两次 Astr 调用都关闭隐藏 SDK 重试。仍失败后，若 `/models` 已为该任务启用跟接，则只调用一次指定外置模型；未启用或跟接也失败时，日记生产立即进入原文证据保底并留下补偿单，不再重复发起近似的完整抽取请求。
- 跟接开关、模型、任务范围和超时现在存入 AstrBot 稳定的 `plugin_data/astrbot_plugin_memos_memory`。首次启动只在稳定位置缺文件时复制旧 `data/astrbot_plugin_memos_memory` 状态，不删除旧文件、不覆盖较新的稳定配置；保存后会重新读取校验，WebUI 明确提示是否已持久化。补偿库也迁到同一稳定目录并纳入周期备份。
- 普通压缩和 23:45 夜间检查点统一采用“事实证据 -> 文学渲染 -> 质量闸门”。本地保底保留全部真正的承诺/边界，再从情景前中后选取代表性因果和感官线索；完整逐轮内容仍在原文档案，不用日记重复承担原文职责。
- 日记提示改为第一人称情景弧：少量细节落笔、围绕关系或情绪转折展开、以余韵收束。明确禁止一轮一句、连续“他说/我说/然后/接着”、括号舞台动作串联，以及为了 supporting 覆盖率逐条改写证据。
- 每篇按自己对应的原文区间检查压缩比、长度、舞台动作比例、逐轮连接词和 supporting 过饱和。首次不合格只做一次定向重写；仍不合格则保留原文与缓冲等待补偿，绝不把换词后的流水账当成功日记写入 Memos。
- 默认单批硬上限由 6 调整为 3。夜间同日连续情景默认目标 1 篇，密度与软候选只增加识别容量；只有跨公历日期或真实两小时以上停顿才硬增加篇数。普通压缩仍可在 1-3 篇内按真实独立场景伸缩。
- 紧凑证据恢复每轮最多保留 220 字视图，避免所谓“紧凑重试”再次发送近乎完整的长提示。传输路线已耗尽时直接转原文证据保底，减少无意义等待与重复黄色告警。
- 旧画像在 RC8 中收敛为低频“长期身份核”：只保留跨月稳定的人格、关系定位、承诺和边界，每轮默认最多注入 1000 字。自动更新至少间隔 30 天，并且必须新增 8 条有效人格/关系/重要证据，普通日常不会反复重写画像。
- 滚动状态改为“有效变化轴”驱动：关系、承诺边界、行为倾向、近期情绪和未决事项最多五类，默认累计 4 类且距上次普通更新至少 72 小时才融合；明确承诺、边界或关系转折仍即时更新。最长等待 7 天只在确有变化时触发，纯重复日常只清理状态任务，不删除 Episode、日记或原文。
- 状态模型只是换一种说法时不再创建新版本。主 WebUI 的“人格与状态”页会同时展示长期身份核、稳定事实、当前滚动状态、下一次融合判断、待处理变化和两套历史版本。
- 模型补偿改为真正的后台任务：页面会显示等待、重建、快照、写回、回滚等阶段及百分比，关闭页面不会中止任务。同一原文批次只允许一个补偿任务；插件进程重载会把未完成任务标记为“重载中断”，保留全部请求数据并允许重新提交。
- 已经发布过保底日记的批次不再逐篇各自重写，而是从完整原文批次重新取证和分篇。只有篇数可与原 Memos 身份安全对应、所有新稿均通过质量闸门时才原位替换；中途任一写回失败会把已替换项目回滚。非日记任务仍可在补偿页查看成功取回的模型结果。
- 夜间大批次的首次完整证据抽取不再暗中嵌套一轮外置 API 跟接，也不会为同一原文创建两张重复补偿单；首次路线失败后进入一次紧凑恢复，紧凑路线才按配置使用 Astr 与外置跟接。这使共享截止时间重新成为真实上限，同时保留质量优先的第二条模型路线。

直接覆盖安装并重载即可。RC8 不自动重写旧日记，不需要 `/memos-sync`、`/memos-reindex` 或重建原文索引；既有用户自己设置的篇数上限继续保留，只有缺省配置采用新的上限 3。

### 6.0.0-rc6ultraOptimize 更新说明

本版继续收紧插件内部模型调用链，不改变主聊天回复模型、检索与注入策略、事件时间归属、既有原文或日记。针对 AstrBot `v4.26.8` 的 OpenAI Provider，另提供独立核心补丁；插件 ZIP 本身不覆盖 AstrBot 核心。

同版本后续构建把身体节律切换为月历锚定：`2026-06-19` 表示从该日开始、以后每个月以19日为周期首日，不再按固定28/30天累计漂移。29至31日锚点在较短月份自动落到当月最后一天。旧 `body_cycle_length` 仍保留在设置文件中以便回滚，但不再参与日期计算；WebUI 会显示本轮和下轮的明确公历首日。未来锚点在日期到来前不会倒推成一个伪周期。

- Astr Provider 请求可向 SDK 传递真正的单次超时。指定 `request_max_retries=1` 时，Provider 外层与 SDK 隐含重试均限制为一次；普通 AstrBot 聊天请求仍保持原来的默认重试行为。还修正了“恰在最后一次尝试成功却仍被判失败”的条件。
- 模型返回了推理内容但没有最终文本时，现在记为 `empty_final` 失败，不会误记成功；日记生产交给原有质量重试，不会把空稿或拼贴稿写入 Memos。
- 长批次证据抽取对**同一提示词、同一 Provider**的近期超时或空输出做短期冷却；新的对话仍正常抽取。冷却时从保留的原文构建有来源的 Episode，文学渲染仍必须通过第一人称、证据覆盖和原文拼贴检查，不合格就保留原文待重试。
- 中等长度的本地恢复只压缩送入文学渲染的证据视图，不删除 Episode 原始证据。调用记录增加提示词指纹、模型输出长度、结束原因和可用时的 token 计数；不保存提示词正文、回答或密钥。

直接覆盖插件 ZIP 并重载即可，不需要同步、重建索引或迁移数据库。要获得 Astr 原生 OpenAI Provider 的 SDK 级超时与单次重试效果，需在**完全匹配的 AstrBot `v4.26.8`**上单独应用核心补丁并重启 Astr；升级 AstrBot 后应重新核对补丁。未应用补丁时插件仍有外层截止时间和质量闸门，但 Provider/SDK 的内部重试可能继续占用后台请求。外置独立 API 的单次请求限制不依赖此补丁。

### 6.0.0-rc6 更新说明

RC6 集中修复插件内部的模型调用、日记生产和心潮感知链路。它不改变 AstrBot 主回复模型、检索/注入路线、时间归属、既有日记或原文档案。

- 心潮独立 API 现在也经过插件调度器，统一记录排队、调用、超时与故障。心潮自身的感知健康保护保留，调度器不再叠加第二个心潮任务熔断。即时任务排队预算默认 0.75 秒；旧配置低于 0.5 秒时按 0.5 秒运行。

- 独立 API 的 `request_max_retries=1` 现在确实只发起一次 HTTP 请求，不会被客户端误解为“一次额外重试”。后台脉络仲裁的重试共享一个总截止时间；证据抽取跑满预算后不再追加一轮完整紧凑调用。
- 外置模型池的证据抽取、兼容压缩、文学渲染会按任务的 120/150 秒预算运行，不再被旧版单模型默认 60 秒提前截断；文学渲染可申请更高输出预算，但用户为某模型设置的输出上限仍生效。短时心潮任务保持短预算。各任务原有 Provider 选择不被自动覆盖。

### 6.0.0-rc5 更新说明

RC5 修复 Live2D 角色在鼠标进入人物区域后头部突然歪斜、脸部与发丝视觉脱节的问题。鼠标不再直接大幅驱动整颗头，也不再参与侧倾参数：现在使用带中心死区的非线性输入，只产生轻微眼神跟随和受限头部补偿；角色动作播放期间暂停鼠标追踪，鼠标离开或停止后在 720ms 内进入平滑回中。

浏览器验收新增桌面、平板和手机三种尺寸的角色边缘追踪测试，会检查 `AngleX/Y/Z`、眼球参数上限、动作期间隔离、离开后的回中状态及实际截图。

**日记生产事故修复：**RC4 中证据抽取和文学渲染连续超时后，本地原文保底可能被当成正式日记发布。RC5 对证据优先流程增加禁止发布闸门：文学渲染失败或质量检查不通过时保留原文与待压缩缓冲，不再写入机械拼接稿；失败批次有短暂重试冷却，避免每分钟重复调用。已归档的旧回退稿不会静默重写。

已有坏稿可在 WebUI 的“记忆生产”页面查看“待文学重建”。修复时直接从保留的原始轮次重建确定性证据，跳过曾超时的 LLM 抽取阶段，仅调用文学渲染并执行原有质量闸门；先生成预览，检查第一人称文学性、事件时间和事实后，再确认**原位替换同一 Memos 条目**。插件会同步更新日记索引与 Episode 视图，并保留旧 Memos 内容和 Episode 快照供精确回滚。生成失败、预览后原日记被外部修改或索引更新失败时，不提交新稿；回滚或自动补偿不会删除原始对话。升级本身不修复已发布的日记，也不需要执行 `/memos-sync` 或重建索引。此修复使原文库 schema 升至 15、批次状态 schema 升至 6；心潮、时间、遗忘、外置模型池和主召回策略未改动。

### 6.0.0-rc4 更新说明

```text

  ├─ 原始上下文治理
```

## 记忆生产

### 1. 原文先归档

达到正常压缩阈值或触发 23:45 夜间检查点时，插件先把本批聊天按会话、轮次和真实发生时间幂等写入本地档案。原文成功保存后，才进入 Episode 与日记生成。

压缩期间新到达的消息不在本次快照中；只有本次确认完成的序号会从 buffer 删除，后来消息继续留待下一批处理。

### 2. Episode 先于日记

证据提取模型先把原文拆成可追溯场景。每个 Episode 可包含：

- 实际事件时间与时间依据；
- 人物、地点、物件和场景锚点；
- 记忆类型与重要性；
- 情绪前后变化；
- 承诺、边界、关系转折和行为倾向；
- 长期影响、触发线索和未解决事项；
- 必写、支持、仅归档三档证据及其原始轮次。

Episode 提取失败、超时或覆盖校验失败时，系统保留原文和 buffer，并使用受控兼容流程，不会把半成品当作成功提交。

### 3. 第一人称文学日记

日记仍由角色第一人称书写。它不是原文复制，也不是只有要点的冷摘要：事实由 Episode 约束，正文负责情绪过程、关系质感和文学连续性。日记必须覆盖必写证据，但不要求逐句复述聊天。

所有目标日记持久化成功后，批次才标记完成。Memos 暂时不可用时可进入本地降级路径，后续仍能同步。

### 4. 23:45 夜间检查点

每日 23:45 检查未达到普通压缩阈值的完整轮次。篇数由跨日、长停顿、对话密度、场景切分和证据容量共同决定，不按固定轮数硬凑。日记使用事件真实发生时间，不会把 23:45 的处理时间写成白天事件时间。

## 滚动状态

滚动状态不是日记摘要，也不是无限追加的画像。它只维护五项当前结果：

1. 关系位置；
2. 承诺与边界；
3. 稳定行为倾向；
4. 近期情绪底色；
5. 尚未解决的事项。

### 更新机制

1. 日记与 Episode 成功提交后，将该压缩批次写入可靠状态队列。
2. 先用确定性规则评估变化，不额外调用 LLM。评分综合记忆类型、重要性、状态变化、长期影响、未解决事项和必写证据。
3. 身份揭示、明确承诺、边界和关系转折立即触发融合。
4. 普通变化先折叠为关系、承诺边界、行为倾向、近期情绪和未决事项五类有效变化轴；默认累计 `4` 类，并且距上次普通更新至少 `72` 小时。
5. 明确承诺、边界和关系转折可绕过普通冷却立即更新；普通变化最长等待 `168` 小时，但没有有效变化时不会为了到期而重写。
6. 达到条件后，将“当前完整状态 + 尚未处理的新 Episode”交给状态模型，输出一份完整新状态覆盖当前版本。
7. 旧状态保留在版本历史中；当前注入只使用最新版本。若新结果只是高相似度改写，不创建空洞的新版本。
8. 模型超时、无效 JSON 或最终体积异常时不写坏状态，批次标记失败并在后台重试。

### 长期身份核与滚动状态如何分工

- **长期身份核**回答“跨月之后仍然成立的我是谁、我们是什么关系”。默认每轮最多注入 1000 字；自动检查至少间隔 30 天，并要求 8 条新增有效证据。
- **滚动状态**回答“最近发生的事让此刻的我处于什么位置”。它承载短期情绪、近期张力和未决事项，避免把这些内容永久堆进画像。
- 二者与日记、Episode、原文档案并行保存：身份核不替代剧情证据，滚动状态不修改历史事实，更新或清理状态队列也不会删除任何可召回记忆。
- WebUI 的“人格与状态”页面可以查看两者的当前内容、更新资格、触发原因和历史版本；手动重新融合滚动状态不会改写长期身份核。

正式版进一步保证：

- 状态队列按角色作用域隔离；共享数据库或改角色名不会串状态；
- 重复提交已完成批次不会再次融合；
- 融合过程中到达的新批次会在当前任务结束后立即重新检查；
- 已失去 Episode 的孤儿批次会被隔离，不会堵住后续更新；
- 强制重建只清理当前角色队列，并从仍存在的 Episode 重新生成。

默认目标约 `1200` 字，这是融合目标而非机械截断。超过 135% 会要求模型合并同义内容；超过 160% 则拒绝写入。承诺、边界和未解决事项不得为了体积被删除。

## 检索与注入

### QueryPlan

检索 query 不是只取当前一句，也不是把全部上下文硬拼进去。系统从当前输入和受控近期上下文提取：

- 直接意图；
- 人物与实体；
- 关系和情绪线索；
- 时间表达；
- 歧义代词与上下文补足。

只有确实需要上下文消歧时才加入上下文查询部分；明确短查询可以保持精简。

### 全 MEMORY 并行召回

同一个查询在以下载体并行检索：

- Episode 事件卡；
- 日记 passage；
- 原始对话轮次；
- BM25 关键词与专名；
- 时间意图触发的 temporal 路线。

多路命中会合并回同一个 `memo_name`，同一记忆只注入一次。相似记忆不是重复记忆：系统保留不同日期、不同关系阶段和不同因果位置，只在证据明确时做有限对比排序。

### 有原文与无原文

有精确原文链接的旧记忆可以用完整原话、稀有词和对应轮次找回，也可以在注入时附带必要一手证据。只有同批次关联时按弱证据处理，不能伪装成精确链接。

没有原文的旧日记仍可通过兼容 Episode、passage、BM25 与时间路线检索。系统不会伪造原话，也不会因为证据较弱就直接删除或快速沉底；它只是不能参加要求精确轮次的一手证据金丝雀。

### 注入结构

最终注入不是若干篇日记的简单拼接，而是：

```text
当前滚动状态（独立，不占日记条数）
+ 事件核心
+ 第一人称日记视角
+ 相关 passage
+ 必要的一手原文
```

普通问题默认目标约 3 条，叙事和复杂问题可扩展到约 6 条。软字符目标超出时逐条紧凑化，优先保留事件与证据，不按固定尾部粗暴截断。弱结果会触发受限安全网宽搜。

当前时间、日记历史时间、身体节律时间和时间洞察各有明确标签。历史日记统一声明为过去发生的资料，不把它解释为当前刚发生事件。

## 非破坏式遗忘

5.0 的遗忘表示“自然访问难度变化”，不是删除、合并、改写或降低事实可信度。

### 七路机制

1. **可达衰减**：时间只降低无强线索时的自然浮现概率，优先使用事实事件时间。
2. **三态迁移**：记忆在鲜明、潜伏、深层之间渐进变化，跨层需要连续确认。
3. **精确线索救援**：日期、完整原话、稀有人物、物件和事件词可从候选池外找回深层记忆。
4. **渐进呈现**：优先注入事件核心与必要证据，不用整篇长日记淹没上下文。
5. **再巩固**：只有真实进入注入且被回复实际采用的记忆才增强使用与再巩固记录。
6. **竞争性遗忘**：区分同事件复述、同主题不同事件、阶段矛盾和因果链；不把相似当重复删除。
7. **心理显著性**：心潮只提供很弱的当前提示，不能改事实、日期、证据等级或独自救援记忆。

承诺、边界、身份、未解决事项、高价值事件和证据不足旧记忆受到资格门保护。

### Shadow 与来源金丝雀

正式版默认 `Shadow`：可达层记录自己会怎样选择，但不替换或重排 4.6 主召回。异常时立即 fail-open，主请求继续使用成熟召回。

只有手动开启 `memory_access_takeover_enable` 且 ACCESS 安全门全绿时，系统才可在主名单之后额外追加最多一条精确原文金丝雀：

- 不替换、不重排、不挤占原召回数量；
- 必须有精确 turn 归属和足够词面支持；
- 日期浏览和同日歧义查询不接管；
- 注入前再次读取原文，缺失就撤销；
- 回复实际采用后才再巩固；
- 连续未采用会持久熔断。

建议正式使用仍保持 Shadow；金丝雀用于受控长期实验。

### 四档遗忘预设

| 预设 | 适用场景 | 特点 |
| --- | --- | --- |
| 长线灵魂塑形 | 年月级 RP | 最慢衰减、最宽竞争图、最重长期保护。 |
| 全维效果优先 | 推荐默认 | 精确救援、长期效果与维护成本平衡。 |
| 日常均衡 | 普通长期聊天 | 中等半衰期与图规模。 |
| 低成本长记忆 | 资源有限 | 降低维护规模，保留事实与保护门。 |

预设只修改遗忘层数值和开关，并强制保持在线接管关闭。不会覆盖 Token、模型、角色名、URL、端口、路径、时区或 Tier 词表。

## 时间、心潮与身体节律

### 时间边界

每轮只生成一次统一当前时间快照。当前公历时间是最高优先级事实；日记事件时间来自 Episode 或原文；身体节律只描述当前身体底色；历史记忆不会覆盖当前日期。

内置时间洞察从有可靠日期的记忆建立纪念日、近期趋势和季节候选。普通轮次最多给一条高置信环境回声，时间问题才扩大检索；滚动状态只能帮助解释意义，不能充当日期证据。

### 心潮

心潮使用请求前即时评估与回复后结算两路：前路表达此刻的倾向、念头与疲劳，后路结合模型实际回复确认、消解或衰减激活。两路共享同一轮现实时间、身体节律和滚动状态；LLM 超时、残缺 JSON 或失败时回退规则，不阻塞主回复。

心潮对记忆排序的影响受严格上限约束，不得改写事实或制造不存在的关系变化。

### 身体节律

身体层按当前现实时间和角色设置生成克制的身体底色，并根据早晨、午后、夜间等时段微调。周期采用月历锚定：锚点日期的日号是以后每月的首日，实际周期长度随相邻月份变为28至31天；短月份对29至31日锚点作月末夹取。它描述“现在可能怎样感受”，不用于推断历史日记发生时的身体状态，也不是医学预测。

## 上下文治理

插件保留近期原始上下文用于自然对话，同时把过早上下文归档到本地历史。治理按请求保留量、归档阈值和周期执行，避免日记与无限增长的原始聊天同时挤爆上下文。

被归档的聊天不会因此成为 Memos 日记；记忆生产与上下文归档是两条独立链路。WebUI 可以浏览现有与备份对话，并查看每轮注入中状态、日记、原文、时间、心潮与上下文的体积构成。

## Memos 托管与数据

插件可以连接外部 Memos，也可以托管放在 AstrBot 指定目录中的 Memos 可执行文件。自动端口会持久化实际分配结果，重载时优先复用，不会每次随机漂移；手动端口仍可覆盖。

主要本地数据：

| 文件 | 内容 |
| --- | --- |
| `memories.db` | 主日记向量、passage、反馈和部分旧兼容数据。 |
| `episodic_memory.db` | 原文、Episode、状态、向量代际、可达层、评测和审计。 |
| `xinchao_state.json` / 心潮数据库 | 心理驱动力、浮现冷却和结算状态。 |
| `house_state.sqlite3` | 小院离线周期、产物、依据、反馈、点击交互和寄送回执。 |
| `house_settings.json` / `house_secret.json` | 小院普通设置与独立加密密钥；密钥文件不进入普通备份。 |
| 备份目录 | 默认每 14 天生成一次插件数据备份。 |

备份、迁移与重建只作用于插件本地数据。Memos 删除同步只删除对应本地派生索引，并在需要时重建滚动状态；不会凭本地状态反向创造 Memos 内容。

## 心笺小院

`6.0.0-test10` 提供可选的离线心智空间。它默认关闭，不改变主记忆生产、主召回、日记、滚动状态、心潮睡眠或上下文治理。启用后，小院在长时间未聊天期间读取有界快照，生成角色未说出口的短念、未寄信、内心独白、未完话题和梦后余韵；这些内容只保存到独立的 `house_state.sqlite3`，不会写回 Memos，也不会自动变成现实记忆。

### 启用

1. 从主 WebUI 的悬挂信封或 `/house` 进入院落。
2. 点击右上角设置，填写独立的 OpenAI-compatible URL、Model 与 API Key。
3. 测试连接后启用小院；建议保留默认 `6` 小时空闲阈值、每天最多 `2` 条、同类冷却 `18` 小时。
4. “自然联动”开启时，下一次真实聊天只把本周期摘要作为一次性短期心理余韵交给心潮；它不会改变长期画像、Episode、日记或现实事实。

小院模型完全绕开 AstrBot Provider 管理器，使用自己的超时、重试和断路器。API 失败时只跳过本次生成，聊天主链和记忆链继续运行。Key 在 Windows 使用 DPAPI 保存；设置 API 只返回“已配置”与掩码，主插件普通备份包含小院数据库和普通设置，但排除 `house_secret.json`。

### 院落交互

| 位置 | 内容 |
| --- | --- |
| 门边信箱 | 未说出口的短念与可人工确认寄出的信。 |
| 书房案几 | 较长的内心独白、信件和写作状态。 |
| 院中茶席 | 未完成的约定与想继续的话题。 |
| 卧房灯影 | 小院梦后余韵，以及现有心潮梦境的只读历史。 |
| 旧木匣 | 全部历史、生成时间、来源依据、反馈、封存和删除。 |

院落的晨昼昏夜只读取服务器当前真实时间，不读取日记日期。清晨、白昼、黄昏、夜晚各有一张保持同一建筑布局的完整院落背景，切换时先预载再交叉淡入；角色同步使用对应的亮度、色温、饱和度、投影和接地阴影，衣摆底缘做短距离羽化，并由前景暗部轻微遮合，使人物更像站在院中而不是浮在背景上。真实 WebUI 的时段来自 `/api/house/overview`，静态预览才使用浏览器本地时间兜底。

角色拥有 `16` 个独立立绘状态与近景、标准、远景三种稳定构图，共 `48` 种静态场景。每套立绘另有 `5` 个语义微动配置，总计 `80` 个动作配置；和三种构图组合后，是 `240` 个由真实素材支撑的“立绘、站位、微动”组合，不把时段或强度的参数排列冒充新素材。姿势覆盖站立、步行、静坐、跪坐、写字、读书、捧茶、提灯、执扇、读信和初醒。

场景选择按真实时段 `25%`、疲劳 `22%`、心潮驱动力 `25%`、最新小院内容 `18%`、稳定新鲜度 `10%` 评分。它只读心潮现有的十二路驱动力，不触发心潮评估或额外 LLM；睡眠意识状态会额外限制到适合的候选。角色状态会稳定保持 `45-90` 分钟，刷新页面不会乱跳；进入新时段、疲劳跨档、出现新类型的小院内容、意识状态改变或离线周期改变时才允许立即重选。接口会返回分项分数、主导驱动力和备选姿势，便于后续诊断。

Ultra3 将旧的永久循环待机改成一次性微动调度。每个当前姿势只从自己的五个动作中按时段、疲劳、驱动力和小屋内容加权抽取，最近两个动作不会直接重复；动作之间保留 `2-20` 秒静止，最多连续三次，任意一分钟内动作占比不超过 `25%`。左键点击角色会中断当前微动，并按神情与点击历史选择点头、惊讶、靠近、招呼、轻缓或回眸；八秒内重复点击不再触发大动作，一分钟五次后静默三十秒，但仍保留本地文字回应。右键单击会在六套可见神情立绘间轮换并保持当前位置，快速右键两次会保持当前神情并在信箱、书房、院心、树下、茶席和回廊六处位置间移动；单击判定延迟 `360ms`，双击不会误触发一次换神情。这两种舞台操作只改变当前页面，不写心潮、主记忆或服务器角色选择状态，刷新后回到真实数据决定的场景。院落 Canvas 只绘制少量叶片、尘光或夜间微光，并可使用不超过数像素的指针视差。

Ultra4 默认使用透明 WebGL 网格渲染完整立绘，并为每一套姿势分别标定头部、头发、躯干、左右衣袖、裙摆和手持物七个局部区域。`34 x 34` 网格让呼吸、衣袖、发梢、裙摆和道具产生彼此不同的连续位移；点击时的点头、惊讶、靠近、书写和招呼也由局部通道组合，不再依靠整张图片统一摇摆。16 套人物已从四宫格源素材拆为互相隔离的 `704 x 704` RGBA 纹理，最外层做轻度抗锯齿；姿势切换会等目标纹理加载完成后一次性提交，不会出现头部横条、相邻格碎片或新姿势套旧纹理。CSS 轻量回退与 WebGL 使用相同独立素材。它仍是“单张完整立绘上的局部网格形变”，不是拆层 Live2D，因此不会伪造眨眼、口型或被原图遮挡的内部结构。

设置中可在“网格 2.5D”和“轻量立绘”之间切换，也可关闭总动效、环境微动或视差，并选择轻柔、平衡、鲜明三档。WebGL 不可用、页面转入后台、系统开启“减少动态效果”或用户选择轻量模式时会自动回退到 CSS 立绘；回退不会影响院落交互。带 `preview=1` 的静态预览会自动巡游 16 套姿势和院内位置，便于直接看到茶席、案几、窗边等坐姿；真实小院不启用演示巡游，仍由服务端的真实时段、疲劳、心潮和内容状态稳定选景。全部动效只在浏览器本地运行，不调用 LLM、不写入主记忆，也不增加提示词 Token。

### 时间与现实边界

- `current_time`：服务器当前真实时间，只决定院落光照和角色当前活动。
- `last_conversation_at`：本次离线周期从何时开始。
- `artifact_created_at`：信件或短念生成时间。
- `source_event_time`：作为依据的历史记忆发生时间，不能覆盖当前时间。
- 梦境、小院产物和离线余韵均明确标记为内心或非现实，不可作为“真实发生过”的证据。

回聊时先冻结离线周期，再执行纯本地摘要与心潮联动；不会在 ProviderRequest 中等待小院 LLM。冻结后才返回的模型结果会标记为 `late_result` 并拒绝保存。一个离线周期只联动一次，同一产物进入梦境、心潮或寄送时都有消费账本；未真正追加到请求的余韵不会被提前清除。

在线脉络路线严格复用本轮已经完成的 5.1 命中，不再次运行 embedding、BM25、rerank 或 LLM，也不减少、替换、重排原日记与证据份额。统一 `context_composer` 只在查询确实涉及当前状态、关系演变或未完成事项时生成小块：最多一个当前事实、必要反证、2-5 个按事件时间排列的节点、状态变化和最多一个未来事项。与基线日记属于同一 Episode、memo 或原文 turn 的正文会在对象层去重；不同日期的相似事件不会被模糊折叠。

当前现实时间、历史事件时间、Memos 创建时间、身体节律时间和未来事项时间窗继续使用不同语义。Canary 注入要求存在有效 `CurrentTimeContext`；内部 ID、评分和算法名不会进入 prompt。附加块受字符硬上限、相对增长软上限和延迟门保护，超限先压缩 supporting 节点，当前事实、反证、状态变化和前瞻事项无法完整表达时整块放弃，不静默截断。

每次在线判断都会写入现有 `thread_query_observations`：稳定桶、是否抽中、5.1 命中数、线程路线、去重、字符与估算 token、增长率、保护/裁剪项、延迟和 fail-open 原因。`/threads` 新增 Canary 观测页，Console 与 WebUI 读取同一 SQLite 数据。任何线程库错误、状态冲突、时间块缺失、组合验证失败、超时或观测写入失败都只关闭本轮 6.x 块，已经完成的 5.1 请求直接继续，不重复召回。

当前 5.1 是 5.x 完整主题尚未全部接管前的中间基线。test7 将上游结果视为冻结接口，而不是把 5.1 的临时参数写死进脉络算法；未来完整 5.x 主路完成后可替换上游候选，Canary 选择、脉络派生、组合器、时间边界和观测协议无需重写。

## 5.0.3

5.0.3 重新校准普通的 25-30 轮压缩：连续剧情按约 16 条消息增加一个软容量，50-60 条消息通常最多生成 4 篇，但跨日期、长时间断层仍会保留为独立事件。篇数是“最多”，LLM 可以在内容不足时少写，避免为了凑数切碎日记。

本版还统一了插件通过 AstrBot 发起的 LLM 调用。每次物理请求明确使用 `request_max_retries=1`，由插件负责有边界的任务级重试，避免 Astr 默认重试与插件重试相乘。心潮即时/后台感知、梦境、主动浮现、时间洞察和画像共享 Provider 健康状态；超时、限流、鉴权或服务不可用后进入短期冷却并使用既有确定性回退。证据抽取、文学日记渲染和滚动状态属于核心任务，不会被可选模块的冷却阻挡。

当所有日记 LLM 路径都失败时，本地保底只保留前 8 条 `must_write` 证据并压缩长证据，不再重复拼接 `detail + quote`，原始对话仍完整保存在原文档案中。
