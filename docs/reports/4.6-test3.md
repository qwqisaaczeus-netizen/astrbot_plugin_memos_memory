# 4.6.0-test3 修复报告

本版以 `4.6.0-test2` 为唯一优化底座，不改心潮、时间、身体节律、检索权重、注入配额及 WebUI 信息架构。

## 修复内容

### 1. 防转录最长公共子串

test2 的滚动哈希递推顺序不正确，只能稳定识别同偏移或整段相同文本，逐字片段位于不同偏移时可能返回 `0`。test3 改为 64 位前缀哈希、二分长度和原文精确复核，仍保持有界复杂度，同时消除哈希碰撞误判。

### 2. 日记渲染最终质量门

test2 只对缺失的 `episode_key` 使用证据保底。如果唯一一次重写仍然存在 must_write 覆盖不足、第三人称报告体或高转录风险，较好的坏版本仍可能被保存。test3 会对“缺失或仍不合格”的每个 Episode 分别使用已核验证据回退，并记录 `grounded_fallback_after:<reason>`。回退文本固定保持第一人称，且只使用该 Episode 已通过溯源校验的内容。

### 3. 原文库路径身份保护

test2 在规范路径已存在时直接选择该文件，即使它为空而旧配置路径含有完整原文。test3 在打开前只读比较数据库 UUID、`source_turns` 与 Episode 数量；发现路径冲突时保留配置指向的已填充库，不覆盖、不合并。插件成功启动后还会在稳定数据目录记录实际库路径，下次升级或 AstrBot 工作目录变化时可以找回最后一次已使用的原文库。绝对路径始终视为操作者明确选择，即使文件尚未创建也不会改写。

### 4. QueryPlanner 线索质量

test2 会把中文上下文拆成连续双字片段，产生“台聊、枚银、色钥”等不可解释噪声。test3 使用 Jieba 词性/分词、角色名、引号实体、关系情绪词和受限地点/物件后缀提取。短指代和叙事追问仍会使用上文；明确查询与时间查询仍保持独立。没有可用实体时只保留上下文参与，不伪造双字实体。

### 5. 测试有效性

test2 有两个 `async` QueryPlan 用例继承自普通 `unittest.TestCase`，运行时实际没有 await。test3 改为 `IsolatedAsyncioTestCase`，并按当前“仅对低置信、无锚点 specific 查询调用 LLM”的真实门控重写断言。

## 数据与升级边界

- 无数据库表结构变更。
- 不改写已有 Memos 日记、原始轮次、情景卡、滚动状态或画像历史。
- 不需要执行 `/memos-reindex`、`/memos-sync` 或重建相似簇。
- 直接覆盖并重载插件即可。
- 首次成功打开原文库后会新增 `episodic_db_location.json` 路径身份文件；它不包含聊天正文。

## 验证结果

- Python 全目录编译通过。
- 针对四项缺陷的新增回归测试通过。
- 完整 `unittest`：`246` 项通过。
- AstrBot 插件发布审计与压缩包结构审计通过。

测试运行环境缺少 `sqlite_vec`，向量测试按插件既有 Python cosine fallback 执行；这不影响 SQLite 原文、BM25、查询规划和注入链路验证。
