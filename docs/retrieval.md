# 6.1.0 检索融合与注入

[流程图](../README.md#检索如何融合并注入) · [架构与边界](architecture.md)

本页依据 6.1.0 源码描述默认精简主路：`lean_recall_enable=true`，且 Episode 索引已经可用。召回负责找候选，最终选择负责决定哪些记忆相关，呈现负责决定正文与证据的长度；这三步使用不同规则。

## 1. 用一个问题同时寻找三种表示

QueryPlan 判断人物、具体/叙事/时间意图及是否需要近期上文。时间约束独立保存；不会无条件把近期聊天拼进每一个查询。主路对规划后的检索文本生成一次查询向量，并复用到：

| 路线 | 检索对象 | 补足什么 |
| --- | --- | --- |
| 日记段落 | 本地 passage 向量与 BM25 词面 | 角色视角、情绪与文学语境；词面保护专名和原话措辞 |
| Episode | 事件卡的语义与词面线索 | 人物、事件、状态变化、承诺和未决事项 |
| 原始轮次 | 归档聊天的向量与词面 | 日记或事件卡省略的细节，回连到相关 Episode / 日记 |

有具体时间意图且可提取日期键时，增加本地 temporal 候选，不另生成查询向量。当前作用域中已发布、激活的 6.1 证据也通过词面索引补充候选；这条证据路线本身不重新生成 Embedding。

Episode 单独命中的日记会在该日记范围内再定位最佳段落，继续复用同一个查询向量。原文回连优先使用精确轮次绑定；批次级映射是较弱的回退，相关度会折减，不冒充精确引用归属。

实现：[查询规划](../query_planner.py#L368)、[默认主路](../main.py#L9190)、[6.1 证据检索与可见性](../generation_v2/integration.py#L346)。

## 2. 融合的是证据表示，不是把所有文字拼起来

### 段落路：语义 + 词面

默认段落混合相关度为：

```text
段落相关度 = 0.7 × 向量相关度 + 0.3 × 归一化 BM25
归一化 BM25 = 该日记的最佳词面分 / 本次候选的最高词面分
```

BM25 不只给已有向量候选加分。向量没找回的强专名或措辞命中也可独立进入候选，并使用词面救援规则；因此上式不是所有候选的唯一公式。后续粗排还考虑重要性、手动钉选、新近度及当前查询的反馈。新近度只是很弱的排序因素，不能理解为老记忆自动无效。

实现：[向量与 BM25 混合、独立词面救援](../vector_store.py#L593)。

### 跨路：按日记来源汇合

主路按 `memo_name` 合并同一来源的段落、Episode、原始轮次和时间候选，保存各路支持、命中段落位置与原文绑定。同一篇日记被三路命中，最终仍是一个记忆候选。

基础分主要保留较强信号，不把不同路的原始分机械相加。段落与事件同时命中有小幅支持加成；精确原文绑定、两层以上支持、时间范围匹配和问题意图也进入后续校准。这些是检索支持信号，不是程序已经证明内容为真。

配置了 Rerank Provider 时，合并后的候选进入统一重排阶段。送去重排的是事件线索、命中片段、可用证据和元数据构成的候选视图，而不是先回读所有日记全文；未配置或重排失败时继续使用原有检索信号。

在最终资格评估中，正的 rerank 分和粗排分均可用时：

```text
粗排信号 = max(候选 score, 候选 relevance)
资格基础分 = 0.78 × rerank 分 + 0.22 × 粗排信号 + 检索校准
排序分 = 资格基础分 - 近期使用软惩罚
```

缺少有效 rerank 分时使用粗排信号。默认近期重复软惩罚为 `0.08`，仍允许与本轮直接相关的旧项再次入选。精确原文、多层支持、日期匹配等还有各自的资格救援，不是只套一个阈值。

实现：[候选合并与统一重排](../main.py#L9190)、[跨层/意图/时间校准](../retrieval_optimizer.py#L207)、[资格与排序](../main.py#L9760)。

## 3. 选择互补记忆，再决定它怎样呈现

资格筛选后，覆盖选择会奖励新的日期、人物、问题事实、记忆类型、状态变化、承诺和未决事项，惩罚同日高度重复的事实。目标是用少量互补项回答问题，避免相似日记挤满上下文；不删除原文或日记。

默认最少目标 1、普通目标 3、主路最多 6 项，具体数量随意图和资格变化；没有合格候选不会硬凑。ACCESS 在主名单冻结后才按条件补充 T/A 两槽，最多追加两项，不替换或重排主名单。

实现：[互补覆盖选择](../main.py#L9617)。

### 何时用整篇，何时用片段

只有入选项才尝试回读 Memos 正文，再决定注入范围。回读失败或来源不可用时退回本地命中内容；选择了全文模式也不代表远端全文一定获取成功。

| 规则 | 呈现 |
| --- | --- |
| 排名在全文优先名额内 | 用整篇；Episode 候选默认名额 1，非 Episode 日记默认 2 |
| 日记本来较短，或保存了多个相关命中段落 | 用整篇，避免拆散完整上下文 |
| 必要记忆且需要完整过程、时间关系、情感弧或状态变化 | 按候选类型和排名保护完整上下文 |
| 非 Episode 日记遇到叙事或时间问题 | 用整篇；Episode 补充项仍优先片段，除非满足前述全文条件 |
| 其余长日记只提供局部细节 | 使用最相关段落；默认前后各扩展 100 字，尽量补齐完整句界 |
| 关闭混合注入或段落索引 | 原选择逻辑改为全文呈现，之后仍可能被软预算缩短 |

`passage_max_chars=280`、重叠 60 字描述的是索引目标粒度，不是最终注入长度。注入会扩展句界或选择全文，不能据此声称每条记忆固定只有 280 字。

实现：[正文回读](../main.py#L13795)、[全文判定](../main.py#L12974)、[命中片段扩展](../main.py#L13218)。

### 原文不是默认第三份全文

事件核心与日记视角是每条入选记忆的基本结构，原文证据按需附加。默认自适应策略下：

- 精确问题（原话、日期、谁说、承诺、边界等）优先为至多两条入选记忆展开一手证据。
- 普通问题通常不展开原文；遇到承诺/规则、时间救援或未决事项时，优先为至多一条约束记忆展开。
- `episodic_evidence_per_memory` 默认 3。旧 Episode 路线在非精确问题上通常只用一条证据；6.1 证据路线按上限选取事实并附其精确引文。ACCESS 补充项另走其证据条件。
- 没有原始轮次和精确引文时，不将日记推导内容伪称逐字原话。仅存于证据库的事实可以检索，不等于已写进日记正文。

程序组织出的每条历史记忆形态为：

```text
[事件日期 / 距今时间 / 记忆类型 / 整篇或片段]
[事件核心]   事件、变化、承诺边界、未决事项
[日记视角]   第一人称整篇正文，或与问题相关的日记片段
[一手证据]   需要核对且可追溯时附少量原始轮次/精确引文
```

结构提示要求三者冲突时优先一手证据；这是提供给回复模型的使用规则，不等于自动校正所有语义错误。当前时间另有标签，不能用历史日期覆盖它。

实现：[证据展开与每条记忆融合](../main.py#L13017)、[6.1 引文附着](../generation_v2/integration.py#L407)、[注入格式](../main.py#L13242)。

## 4. 软预算与本轮临时注入

默认 `inject_char_budget=10000` 是已组装记忆条目的字符软目标，不是整个模型上下文的硬上限。超出目标时从低排名项开始，将整篇改为相关段落，必要时再改为紧凑摘录，保留事件核心、缩减文学正文与证据。最高排名项保留原先形态，不因这个预算直接丢弃已组装条目，因此仍可能超出目标。

最终历史记忆集合通过 `TextPart(...).mark_as_temp()` 放入本轮 `extra_user_content_parts`。长期身份核、滚动当前状态、当前时间与心潮各有自己的临时内容，不作为这几条检索候选重复融合。

实现：[历史集合使用规则](../main.py#L12927)、[临时请求注入](../main.py#L11642)。

## 回退路径

图中是默认主路，不是所有配置都会走的唯一路线。关闭精简主路且 Episode 可用时采用情景卡级联；Episode 未就绪时走多查询回退。多查询回退使用加权 RRF：`Σ 路线权重 / (k + 该路线排名)`，合并后可统一 rerank。这个 RRF 公式不应被写成默认精简主路的跨层融合公式。

实现：[主路选择](../main.py#L10667)、[回退 RRF](../main.py#L9979)。
